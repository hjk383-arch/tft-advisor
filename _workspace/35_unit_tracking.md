## 1. 규칙 (`vision/unit_track.py`)

### 1.1 구매 → 칸
- 구매 신호 = 상점 칸이 챔피언 → 빈 칸(인식기가 이 프레임 상점을 읽었을 때, 2칸 이하 변화) 또는 app 장부 `buy` 이벤트
  (`LiveLoop._feed_unit_namer` → `note_purchase`). 같은 챔피언의 두 출처 보고는 `BUY_WINDOW_S`(3초) 안에서 한 건.
- 산 유닛은 **가장 왼쪽 빈 벤치 칸**에 ★1로 떨어진다(TFT 규칙). 새 칸마다 "직전 프레임 빈 칸 목록에서의 순번"(`rank`)을 적고,
  같은 프레임에 n칸이 생기면 순번이 정확히 0..n-1이어야 구매 칸 후보다. ★2 이상 새 칸은 구매가 아니다.
- 창 안의 남은 구매 수 = 후보 칸 수일 때만 시간 순 구매 ↔ 칸(왼쪽부터)으로 짝짓는다(`source="purchase"`, 0.9). 다르면 아무것도 붙이지 않는다.
- 장부 이벤트가 한 프레임 늦게 와도(새 칸이 먼저 보임) 창 안이면 짝짓는다. 직전 벤치를 모르는 첫 프레임의 칸은 후보가 아니다.
- **합성 구매**: 새 칸 없이 기존 칸의 배지 성급이 오르고(창 안) 그 챔피언 구매 한 건 → 그 칸 = 그 챔피언(이미 이름이 있으면 같아야).
  나머지 사본 칸은 사라져 대기 → 만료된다. 어느 칸이 남는지는 캡처로 확인하지 못했다 — 배지가 오른 칸을 그대로 쓴다.
- 구매가 기다리는 중이면 그 가장 왼쪽 빈 칸의 새 칸은 옮기기 후보에서 뺀다(같은 프레임에 다른 유닛이 벤치를 떠나도 헷갈리지 않게).
- 확인 한계: "가장 왼쪽 빈 칸" 규칙 자체를 캡처 쌍으로 검증하지는 못했다(연속 캡처 없음). 대신 그 칸이 아니면 붙이지 않는다.

### 1.2 옮기기·자리 바꾸기
- 모델 기술자 닮음(`units.similarity`). 실측(옛 판 준비 캡처 4장, 확인 라벨): 같은 칸 같은 유닛 중앙값 0.74, 옮긴 같은 챔피언 5% 0.43,
  다른 챔피언 95% 0.40·최대 0.59, 같은 프레임 다른 유닛 최대 0.56(live4 오른/알리스타). 같은 챔피언 두 사본끼리도 0.51.
- 하나 사라지고 하나 생김(끌어 옮기기 한 번, 대기 정체 없음): 닮음 >= 0.35이고 성급이 맞으면 같은 유닛.
- 여럿: 닮음 >= 0.50이고 행·열 모두 2위보다 0.12 이상. 애매하면 **짝짓지 않고 정체를 버린다**(`dropped`).
- 벤치 칸 위로 끌어 놓으면 두 유닛이 자리를 바꾼다: 그대로 있는 두 칸의 엇갈린 닮음(각 >= 0.45) 합이 곧은 합보다 0.30 이상 크면 바꾼다.
- 그대로 있는 칸도 닮음 >= `KEEP_MIN`(0.55)이어야 정체를 유지한다(전투 중 팔고 같은 칸에 다른 유닛을 산 경우). 표본은 닮음 >= 0.6이면
  매 프레임 새 그림으로 바꿔 자세 변화를 따라간다.
- 사라진 정체는 `LIMBO_S`(6초) 동안 대기 → 다시 나타나면 이어 붙이고, 아니면 지운다(판매·합성으로 사라진 사본). 장부 `sell`은 대기 정체를 바로 지운다.

### 1.3 vision 이름과 합치기(틀린 이름 0)
- 칸의 확실한 vision 이름(특성 구속·같은 모델·뒷받침된 사진 비교, >= 0.75)은 정체로 받는다 → 그 뒤로 옮겨도 이름이 따라간다.
- 정체와 확실한 vision 이름이 다르면 **둘 다 버린다**(`conflict`). 뒷받침 없는 추정 이름은 정체를 이기지 못한다.
- 출력 `name_source`: `purchase`(산 칸에 그대로) | `tracked`(옮긴 뒤·vision에서 받은 정체), `corroborated=True`.
- 보드 `unplaced`(특성 집합 중 칸 미상)는 이름이 붙은 만큼 줄인다.

### 1.4 체력바 없는 프레임·다른 화면
- `bench_held` 프레임(준비 끝)과 준비 단계가 아닌 화면(아이템 선택 등)에서는 **갱신하지 않고** 칸 열쇠로 이름만 붙인다.
  `bench_memory`가 "그대로"(`held`)라고 한 칸만 — 애매한 칸(이제 `none`, 성급·아이템 없음)에는 붙이지 않는다.
- 맵 서명(`unit_db.arena_signature`)이 바뀌면(`units.same_arena` 아님) 새 판으로 보고 비운다. 새 판은 루프가 `unit_tracker.reset()`.

### 1.5 연결
- `Recognizer.recognize`: 이름 판정 → `bench_memory.apply` → `unit_tracker.update(read, 기술자, 시각, shop=이번 상점, active=준비,
  arena=맵 서명)`. 기술자는 `UnitNamer.last_descs`(이름 판정과 같은 순서) — 다시 계산하지 않는다.
- `app/loop.py`: `_feed_unit_namer`가 장부 `buy`/`sell` 이벤트를 `recognizer.unit_tracker`에 알린다. `_do_reset`이 `bench_memory`와
  `unit_tracker`를 비운다.
- `app/unit_merge.py`: vision 이름이 이미 장부 순서보다 우선한다(규칙 1) — 추적 이름은 vision 이름으로 들어간다. 바꾼 것은 성급 기본값뿐(§2).
- 사진 수집기(`unit_db.UnitCollector`)는 그대로: 구매로 이름이 정해진 벤치 크롭이 30 정책(벤치만 · 승인 3장이면 그만)대로 모인다.

## 2. 성급

### 2.1 배지 판독 정확도(원본 캡처 전체, 라벨의 `star`)
| 라벨 → 판독 | 칸 |
|---|---|
| ★1 → ★1 | 111 |
| ★2 → ★2 | 17 |
| ★1 → 칸 없음 | 3 (live3 2-3 준비 끝, 체력바 없음, 한 장만 — 앞 프레임과 이어 읽으면 `held`로 ★1 유지) |
| 모름(라벨 None) → 칸 없음 | 3 (같은 프레임) |
| 틀림 | **0** |
- ★3 배지는 캡처가 없어 팔레트가 없다 → 배지는 보이는데 ★1·★2가 아니면 None(모름). ★3을 한 번 캡처하면 `STAR_PALETTE[3]`를 채운다.
- 배지가 가려지면(전략가 이름표가 바 **왼쪽**까지 덮음) 그 유닛은 체력바 조건(배지 필수)에서 빠진다 → `missed_board`로 드러난다
  (23 보고). 아이템 아이콘은 바 아래라 배지를 가리지 않는다.
- live4 라벨을 새로 적었다: 보드 넷 ★1, 벤치 0·3 ★2, 1·2·4 ★1(배지로 확인).

### 2.2 모르는 성급은 None
- `bench_memory`: 그림이 바뀌었는데 기준이 없어 애매한 칸은 이름·성급·아이템을 모두 버린다(`name_source="none"`, `star=None`).
  QA 32 W1(strict xfail)을 통과 테스트로 바꿨다. "그대로"인 칸만 성급을 유지한다.
- 추적기: 배지 > (같은 칸에 그대로·닮음 >= 0.55인) 정체의 성급 > None. 옮긴 유닛은 자기 성급을 가지고 간다. 합성은 배지가 오른 것으로 안다.
- `unit_merge`: vision 이름 칸의 성급 = 배지 > 장부 > **None**(예전 1). `UnitOnBoard.star`는 계약상 `Star | None`이라 None을 그대로 쓸 수 있다.
- **jev-strategist에게(고치지 않았다)**: advisor가 None을 1로 본다 — `advisor/board_plan.py:80,329,345`, `candidates.py:236`,
  `engine.py:102`, `features.py:396,400,406`, `sell.py:46,125,152,153,176`의 `star or 1`. 배치·판매 추천이 성급 모름을 1성으로 가정하지
  않게 하려면 이 자리에서 None을 "모름"으로 다뤄야 한다(예: 판매 후보에서 빼거나, 2성 가능성을 남기기).
