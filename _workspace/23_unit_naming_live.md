## 1. 보드: 가려진 유닛 (`vision/board.py`)
- 2-3 프레임 (1,1) 유닛: 체력바 x 685~692, y 426~430만 초록(나머지는 이름표의 레벨 상자 "4" 밑). 왼쪽 성급 배지 윤곽은 보인다.
- `BAR_MIN_W` 18 → 6 /1080. 바 후보는 여전히 **성급 배지 윤곽 45px 이상 + 위 테두리(어두운 2px, 그 위 밝음) + 두께 2~7줄**을
  모두 통과해야 한다. 바 가운데 = 왼쪽 끝 + 만피 길이/2라서 일부만 보여도 자리가 맞다.
- 전략가 이름표 바: 두께 13px(유닛 4~5px) → `BAR_MAX_H`에서 탈락, 왼쪽은 성급 배지가 아니라 회색 레벨 상자.
- 회귀: 원본 11장 보드·벤치 판독(`test_raw_board_labels_match_read`, `test_raw_board_counts_match_watermark`) 그대로 통과.
- 남은 한계: 바 **왼쪽**(배지)까지 가려지면 여전히 못 찾는다 → 이제 `missed_board`(특성 풀이 크기 - 찾은 칸)로 드러난다.

## 2. 특성 풀이 ≠ 찾은 칸 수 (`vision/units.py name_units`)
- 찾은 칸 n으로 풀이가 없으면 n+2까지 다시 풀고, **모든** 풀이 크기가 n보다 크면 쓴다. `missed = 최소 풀이 크기 - n`.
- 배정: 풀이 챔피언 k > 칸 n이면 닮음 0인 가상 칸 k-n개를 더해 `slot_values`(모든 챔피언 최소 1회) 그대로 푼다.
  실제 칸만 이름을 받는다. `unplaced`는 계약대로 "이름 없는 칸 수와 같을 때만"이라 가려진 유닛이 있으면 비운다.
- `BoardNames.common` / `BoardRead.board_common`: 모든 풀이에 든 챔피언(= 풀이가 여럿이어도 보드에 **확실히** 있다).
  라이브 2-3: 풀이 {요릭,카르마,이즈리얼} / {요릭,유나라,르블랑} / {아리,이즈리얼,요릭} → 공통 요릭.
- 풀이가 여럿일 때 라이브러리 이름은 풀이 합집합 안에서만(기존) + 이제 순위·차를 **라이브러리 전체**로 잰다
  (후보를 먼저 줄이면 표본 있는 후보가 2위 없이 1위가 되는 구멍이 있었다).

## 3. 라이브러리 이름: 두 단계 + 여러 프레임 일치 + 맵 견고성
### 3.1 측정(교차 맵)
라벨이 없는 칸도 **같은 모델끼리**는 눈으로 묶을 수 있다: 분홍 날개(옛 판 벤치 6·라이브 벤치 4·5-5/Anvil), 금색 날씬한 갑옷
(옛 판 벤치 0 · 5-5/Anvil), 초록 딱정벌레, 불꽃 묘목, 오른 등 12묶음 · 맵 3종(옛 돌 / 푸른 돌 5-5·Anvil / 모래 라이브 2).
"다른 맵의 같은 모델" 26칸을 질의로, 다른 맵 표본만 라이브러리로 두고 1위 이름을 냈다(스크립트: 스크래치 `exp.py`).

| 배경 제거 | 같은 모델 닮음 평균 | 다른 모델 최대(p99) | (0.50, 0.10) 맞음/틀림 | (0.60, 0.15) 맞음/틀림 |
|---|---|---|---|---|
| 테두리 3군집(옛) | 0.625 | 0.535 (0.509) | 23 / 3 | 18 / 0 |
| **테두리 4군집(채택)** | 0.679 | 0.513 (0.482) | 24 / 5 | **23 / 0** |
| 테두리 6군집 | 0.681 | 0.488 (0.450) | 24 / 1 | 23 / 0 |
| 3군집 + 맵 전체 바닥 색 8군집 | 0.605 | 0.603 | 21 / 11 | 18 / 1 |

- 맵 전체 바닥 색을 빼는 방법은 모델의 주황·금색까지 지워 더 나빴다. 테두리 군집 수를 늘리는 쪽이 낫다.
- 6군집은 교차 맵은 가장 좋지만 같은 맵 보드 배정 여유(아칼리/코그모)가 0.19 → 0.13으로 줄어 4군집을 골랐다.
- 옛 임계(0.50/0.10)는 어느 설정에서도 다른 모델을 1~5칸 이름 붙였다 → 라이브 실패와 같은 종류.

### 3.2 규칙(`_tiered_library_name`)
- **뒷받침된** 이름(1위 챔피언이 이번 프레임 보드에서 확정 · 보드 집합/공통 · app 힌트): 0.55 / 차 0.12, 신뢰도 상한 0.90.
- **뒷받침 없는** 이름: 0.62 / 차 0.20, 신뢰도 상한 0.75(세션 메모리 학습 0.85 아래 → 자기 강화 없음), `corroborated=False`.
- `UnitNamer._agree`: 뒷받침 없는 이름은 같은 칸(벤치 칸/육각칸)에서 **연속 2프레임** 같은 이름이어야 내보낸다(`AGREE_FRAMES`).
  칸이 비거나 다른 이름이 나오면 처음부터. 스크린샷 한 장 평가(테스트)는 `agree_frames = 1`.
  주의: 같은 그림 두 프레임이면 일치는 공짜다 — 이 장치는 끌기·효과 같은 순간 오류용이고, 열린 집합 오류는 3.1의 임계가 막는다.
- 힌트: `UnitNamer.set_hints(ids)` — 이번 판 보유로 알려진 챔피언(장부 구매). 이름의 **뒷받침**으로만 쓴다(힌트만으로 이름 없음).
  라이브 2-3에서 힌트 {오른, 아칼리}: 벤치 3 = 오른(0.589/0.266 → 뒷받침 임계 통과), 벤치 2는 여전히 모름(아칼리 0.46).
- 상점 "본 적 있는 챔피언"은 뒷받침으로 쓰지 않았다: 몇 번 새로고침하면 1~2코스트 풀 대부분을 보게 되어 증거가 약하다.
  **산** 챔피언(장부)이 강한 증거라 힌트 API로 받는다(§6 app 연결).
