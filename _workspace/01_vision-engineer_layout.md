## 2. 인식 대상별 전략

| 대상 | 방법 | 근거 / 세부 |
|---|---|---|
| **상점 5칸** | 이름 칸 OCR(RapidOCR, 한국어 rec 모델) → `rapidfuzz.process.extractOne`로 정적 챔피언 이름(ko/en) 매칭. 점수가 85 미만이면 `None` | 이름 텍스트가 선명하고 위치가 고정돼 있다. 시즌이 바뀌어도 이름 목록만 갈면 된다. 빈 칸(구매 완료)은 이름 칸의 분산이 낮은 것으로 감지한다. 비용은 챔피언 이름에서 정적 데이터로 도출한다(인식할 필요 없음). 테두리 색은 교차 검증용이다 |
| **증강 제시 3개** | 이름 칸 OCR → 퍼지 매칭 → 설명은 정적 데이터에서 가져온다 | 설명 OCR은 긴 한글 문단이라 오류가 많다. 이름만 읽고 설명은 DB에서 조회한다. 실버/골드/프리즘 등급은 카드 테두리 색으로 보조 판별한다 |
| **보유 증강** | **선택 순간 기록 방식.** 증강 화면이 보인 마지막 프레임의 3개 후보를 저장하고, 화면 전환 직후 (a) 사용자가 오버레이에서 확인하거나 (b) 직전 프레임에서 선택 강조(카드 하이라이트)를 감지해 확정한다. 게임 세션 단위로 영속화한다(`_state/session.json`) | 증강은 선택 후 HUD에 아이콘으로만 작게 남는다(위치 미확인, E: 왼쪽 특성 패널 위나 내 초상화 근처). 아이콘 매칭은 2차 수단이다. 앱을 중간에 켜면 보유 증강을 알 수 없으므로 수동 입력 UI가 필요하다 |
| **아이템 재료/완성템** | 아이템 벤치 10칸 크롭 → OpenCV `matchTemplate`(TM_CCOEFF_NORMED, 그레이 + 컬러 히스토그램 보조), 템플릿은 CommunityDragon 아이콘을 슬롯 크기로 리사이즈해 만든다 | 텍스트가 없고 아이콘은 고정 디자인이다. 재료가 약 9종, 완성템이 약 50종이라 후보 공간이 작다. 슬롯이 빈 경우는 배경 분산으로 거른다. 0.8 미만이면 `None`. 게임 내 렌더링은 원본 아이콘과 테두리·조명이 달라서 **실제 화면에서 잘라낸 템플릿으로 교체하는 단계**를 계획한다 |
| **골드/레벨/스테이지/HP 숫자** | 1순위 **숫자 글리프 템플릿 매칭**(0–9, `-`, `/`), 2순위 RapidOCR | 폰트가 고정이고 글자 종류가 12개뿐이다. OCR보다 약 10배 빠르고 결정적이다. 첫 fixture에서 글리프를 잘라 `data/templates/{set}/digits/`에 둔다. 글리프가 만들어지기 전 부트스트랩 단계는 OCR로 처리한다 |
| **활성 특성 패널** | 특성 아이콘 템플릿 매칭 + 옆의 숫자(현재/다음 구간) 글리프 매칭. **또는** 보드 유닛에서 특성을 계산한다 | 가능은 하지만 패널이 스크롤되거나 접히고(특성이 많으면 일부만 보임) 아이콘이 작다. **MVP에서는 보드 인식 결과 + 정적 데이터로 계산**한다. 패널 판독은 교차 검증용 Phase 3이다 |
| **보드/벤치 유닛** | (1) 벤치: 체력바 픽셀(초록/빨강 가로 막대) 유무로 점유 여부 → 체력바 위쪽 별(★) 개수 색 판별 → 유닛 식별은 어렵다. (2) 보드: 헥스 중심 주변 체력바 탐지. 유닛 식별은 3D 모델이라 템플릿 매칭이 불안정하다 | 가장 어렵다(모델 애니메이션, 스킨, 원근, 겹침). 현실적인 대안: **상점 구매 추적**(상점 칸이 사라지고 골드가 비용만큼 줄면 해당 챔피언 구매로 기록) + 사용자가 유닛을 클릭했을 때 뜨는 정보 패널 이름을 OCR + 오버레이에서 수동 보정 |

OCR 전처리: ROI를 2~3배로 업스케일하고, 그레이 변환 후 Otsu 또는 흰 글자 임계값을 적용한다. 한국어 클라이언트 여부가 미확정이므로 ko/en 이름을 둘 다 퍼지 후보로 넣고, 먼저 맞는 쪽으로 언어를 자동 고정한다.

## 3. MVP 범위 제안

| 단계 | 포함 | 목표 정확도 (fixture) |
|---|---|---|
| **MVP (Phase 2)** | 스테이지, 골드, 레벨(+XP), 상점 5칸, 증강 제시 3개 + 선택 기록, 아이템 벤치 10칸, 화면 상태(일반/증강/기타) | 숫자 ≥ 98%, 상점 이름 ≥ 95%, 증강 이름 ≥ 95%, 아이템 ≥ 90% |

## 4. 화면 상태 판별안

신호를 싼 것부터 순서대로 확인한다. 모두 픽셀 기반이다.

1. **로딩/비인게임**: 상점 띠 ROI와 골드 ROI의 평균 밝기와 분산이 매우 낮거나, 새로고침 버튼 앵커 템플릿 점수가 0.6 미만이고 스테이지 ROI를 OCR로 읽을 수 없는 상태.
2. **증강 선택**: 증강 이름 칸 3개가 모두 텍스트 분산이 높고, 증강 리롤 버튼 3개(y 0.81) 앵커 템플릿이 일치함. 보조 신호: 스테이지 문자열이 2-1, 3-2, 4-2 직후인지(세트마다 다를 수 있음, 미확인).
3. **캐러셀**: 스테이지 문자열이 `N-4`(그리고 1-1)이고 상점 띠가 사라진 상태(캐러셀 동안에는 상점 UI가 없음, E).
4. **게임 종료**: 승리/종료 텍스트 ROI OCR, 또는 '지금 나가기' 버튼 템플릿.
5. **전투 중 vs 준비 단계**: 스테이지 옆 타이머/단계 표시 색(E), 또는 보드 위쪽(적 진영 y 0.15–0.38) 체력바 밀도(전투 중에는 적 유닛 체력바가 가득함). 준비 단계가 상점 추천의 주 트리거다.
6. **아이템 선택(모루/포탈 선택 등)**: 모루 메시지 ROI, 중앙 선택 카드 패턴. 세트별 메커닉이라 **미확인**.
7. 그 밖은 일반 라운드(상점 앵커는 있지만 증강 앵커는 없음).

상태 전이는 3프레임 연속으로 일치할 때만 확정한다(깜빡임 방지). 증강 → 일반 전이 순간을 "증강 선택 완료" 이벤트로 쓴다.

**결론: Python 3.14 venv(`py -3.14 -m venv .venv`)를 권장한다.** 권장 스택은 `mss`, `numpy`, `opencv-python>=4.10,<5`(5.0 메이저 변경 위험 회피, 4.14는 abi3라 3.14에서 쓸 수 있음), `rapidfuzz`, `rapidocr`(3.x) + `onnxruntime`이다.
- EasyOCR은 torch(수 GB)를 끌어오고 `opencv-python-headless`에 의존해 rapidocr의 `opencv-python`과 충돌하므로 **권장하지 않는다**. 대안으로만 남긴다.
- 미확인: 실제 import와 추론 동작, rapidocr 3.x 한국어 인식 모델의 첫 실행 다운로드(네트워크 필요), omegaconf 2.0.0의 3.14 런타임 호환성. 설치 단계에서 스모크 테스트가 필요하다. 문제가 생기면 3.12를 설치(사용자 동의 필요)하고 venv를 새로 만든다.

## 7. 리스크

1. **좌표 노후화**: 출처 A는 2024-04 기준이다. Set 18 HUD 변경 여부를 모른다. 첫 fixture로 전체 재보정을 전제한다.
2. **해상도/UI 스케일**: A가 "다른 해상도는 1080p의 정확한 비례가 아님"이라고 명시한다. 1080p가 아니면 프로파일이 따로 필요하다. HUD 크기 슬라이더가 기본값이 아니면 모든 좌표가 틀어진다.
3. **보드 유닛 인식 난이도**: MVP에서 제외한다. 구매 추적과 수동 보정에 의존하므로, 앱을 중간에 켜거나 전리품으로 유닛을 얻으면 누락된다.
4. **보유 증강**: 선택 순간을 놓치면 복구가 어렵다. 수동 입력 UI가 필수다.
5. **OCR 한국어 품질**: 작은 글씨와 게임 폰트에서 rapidocr 한국어 모델의 정확도가 미검증이다. 퍼지 매칭 후보가 작아서 상당 부분 보정되리라 예상한다.
6. **아이콘 템플릿 도메인 차이**: CDragon 원본 아이콘과 인게임 렌더링(테두리, 축소, 셰이더)이 다르다. 실제 화면에서 잘라낸 템플릿이 필요하다.
7. **의존성**: opencv 5.0 메이저 변경, omegaconf 2.0.0의 3.14 런타임은 미검증이다. rapidocr 모델을 처음 쓸 때 네트워크 다운로드가 필요하다.
8. **캡처 방식**: 전용 전체화면(exclusive fullscreen)에서는 mss가 검은 화면을 잡을 수 있다(미확인). 테두리 없는 창모드를 권장한다.
9. **정책**: 화면 픽셀만 쓰고, 클릭이나 호버 같은 입력은 하지 않는다. 출처 A의 봇 기능(클릭 좌표, 자동 구매 등)은 쓰지 않으며, 표의 "표지용" 좌표는 화면 판별 앵커로만 쓴다.
